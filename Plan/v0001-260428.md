## 기획 항목

### 원페이지 레이아웃 고도화 방향
- 현재 원페이지 구조는 유지하되, 모든 주요 섹션이 `오늘의 날씨 콘텐츠`를 기준으로 연동되도록 데이터 구조를 재설계한다.
- `DailyContent` 형태의 일자별 콘텐츠 모델을 도입한다. 필드 예시는 날짜, 날씨 테마, 담당 멤버 ID, 쇼츠 영상 ID 또는 비디오 소스, 히어로 문구, OOTD 이미지 목록, 추천 플레이리스트, 관련 트랙, 유튜브/틱톡 게시물 링크이다.
- `App.tsx` 내부에 흩어진 콘텐츠 상수는 Supabase 등 별도 DB 없이 `src/data` 하위 TypeScript 상수 파일로 분리하여 데일리 업데이트 비용을 낮춘다.
- 네비게이션은 기존 원페이지 앵커를 유지하되, `MEMBERS`를 `TODAY`, `ALBUMS`를 `PLAYLIST` 또는 `MUSIC`, `SOCIAL`을 `ARCHIVE` 성격으로 재정렬하는 방향을 검토한다.

### 하드코딩 콘텐츠 상수 구현 요건
- 별도 Supabase DB, CMS, 관리자 페이지 없이 저장소 내 정적 TypeScript 상수로 콘텐츠를 관리한다.
- `src/data/dailyContent.ts`에 날짜별 데일리 콘텐츠 목록을 선언한다. 예시는 `DAILY_CONTENTS: DailyContent[]` 또는 날짜 키 기반 `Record<string, DailyContent>` 구조이다.
- `src/data/members.ts`, `src/data/tracks.ts`, `src/data/playlists.ts`, `src/data/socialArchive.ts`처럼 도메인별 상수를 분리해 `App.tsx`가 렌더링에만 집중하도록 한다.
- `src/types/content.ts`에 `DailyContent`, `Member`, `Track`, `Playlist`, `SocialPost`, `LocalizedText` 타입을 정의해 콘텐츠 누락을 TypeScript 단계에서 확인한다.
- 날짜는 `YYYY-MM-DD` 형식으로 통일하고, 오늘 날짜와 매칭되는 콘텐츠가 없으면 가장 최신 콘텐츠 또는 지정 fallback 콘텐츠를 노출한다.
- 이미지와 영상 썸네일은 가능한 `public/images` 또는 `public/daily/{date}` 하위 로컬 에셋 경로를 우선 사용한다. 외부 URL은 플랫폼 임베드나 공식 링크가 필요한 경우에만 사용한다.
- 유튜브 쇼츠/틱톡은 클라이언트 스크래핑 대신 운영자가 상수에 직접 등록한 영상 ID, 게시물 URL, 썸네일 정보를 기준으로 렌더링한다.
- 새 데일리 콘텐츠 등록 시 필수 입력값은 날짜, 날씨 테마, 담당 멤버 ID, 히어로 영상 소스 또는 쇼츠 ID, 히어로 문구, OOTD 이미지 목록, 추천 플레이리스트, 관련 소셜 링크이다.
- 콘텐츠 등록 검증은 `npm run lint`의 TypeScript 검사로 수행하고, 런타임에는 필수 데이터 누락 시 fallback UI를 표시한다.
- 향후 운영 규모가 커질 경우 DB 이전 가능성을 열어두되, v0001 구현 기준은 하드코딩 상수 등록 방식으로 고정한다.

### JP/EN/CN 언어 지원 기획
- 현재 기본 언어는 한국어로 유지하고, 글로벌 방문자를 위해 영어, 일본어, 중국어를 추가 지원한다.
- 내부 언어 코드는 `ko`, `en`, `ja`, `zh-CN`을 사용한다. UI 표기는 각각 `KOR`, `ENG`, `JPN`, `CHN`으로 정리한다.
- `Language` 타입은 기존 `ko | en`에서 `ko | en | ja | zh-CN`으로 확장한다.
- 텍스트 콘텐츠는 `LocalizedText` 타입으로 관리한다. 예시는 `{ ko: string; en: string; ja: string; zhCN: string }` 형태이며, 코드 안전성을 위해 실제 키 명명은 TypeScript에서 사용하기 쉬운 `zhCN`을 검토한다.
- 네비게이션, 버튼, 섹션 제목, 히어로 문구, 멤버 소개, 플레이리스트 설명, 아카이브 카드 문구는 모두 다국어 상수로 분리한다.
- 가사와 고유 음원명은 원문 유지가 필요한 경우 번역하지 않고, 설명 문구와 UI 라벨만 번역한다.
- 언어 선택 UI는 현재 드롭다운 구조를 유지하되 4개 언어를 지원하도록 확장하고, 모바일 메뉴에서도 동일하게 접근 가능하게 한다.
- 브라우저 언어 감지는 선택 사항으로 두고, 사용자가 직접 선택한 언어는 `localStorage`에 저장해 재방문 시 유지한다.
- 번역 누락 시 fallback 우선순위는 선택 언어, 영어, 한국어 순으로 처리한다.
- JP/CN 문구는 줄 길이가 한국어/영어와 다르므로 버튼, 카드, 히어로 타이포그래피에 고정 폭과 줄바꿈 대응을 포함한다.

### 구간 1: 메인 히어로 고도화
- 기존 정적 이미지 히어로를 데일리 쇼츠 기반 비디오 히어로로 전환한다.
- 최상위 배경은 음소거, 자동재생, 반복 재생, 모바일 전체 화면 대응을 기본값으로 한다.
- 유튜브 쇼츠 원본을 그대로 배경으로 자동 연동하는 경우 iframe autoplay 제약과 로딩 안정성 문제가 있으므로, 운영 안정성을 위해 `dailyContent.heroVideoUrl` 또는 하드코딩된 쇼츠 ID 기반 임베드 전략을 함께 둔다.
- 중앙 카피는 `WEATHER IDOLS` 고정 노출보다 `오늘의 날씨`, `오늘의 담당 멤버`, `오늘의 테마`가 즉시 보이도록 개편한다.
- 기존 Spotify, Apple Music, YouTube Music CTA는 유지하되, 오늘의 추천 음원/플레이리스트로 이어지는 1차 CTA와 전체 스트리밍 링크로 이어지는 2차 CTA로 역할을 분리한다.
- 히어로 하단에는 다음 구간 일부가 보이도록 스크롤 유도 UI를 두어 쇼츠 유입 사용자가 자연스럽게 OOTD 상세로 이동하게 한다.
- 데스크탑에서는 9:16 세로형 쇼츠가 과도하게 확대되어 잘리지 않도록 중앙 세로 프레임을 기준으로 배치하고, 좌우 여백은 블러 배경, 색상 오버레이, 보조 정보 패널 등으로 자연스럽게 처리한다.
- 모바일에서는 히어로 쇼츠가 화면 전체를 점유하더라도 하단 콘텐츠 접근을 막지 않도록 섹션 높이를 `100svh` 기준으로 설계하고, 다음 섹션으로 이어지는 세로 스크롤 흐름을 명확히 둔다.

### 반응형 쇼츠 비율 및 스크롤 UX 요건
- 세로형 쇼츠 기본 비율은 `9:16`으로 고정하고, 데스크탑/태블릿/모바일 모두 동일한 원본 비율을 유지한다.
- 데스크탑 히어로에서는 쇼츠 본문을 중앙 세로 프레임으로 노출하며, 프레임 최대 높이는 뷰포트 높이를 넘지 않도록 제한한다.
- 데스크탑 쇼츠 갤러리는 카드별 `aspect-ratio: 9 / 16`을 유지하되, 한 화면에 3~4개 카드가 안정적으로 보이도록 카드 최대 폭과 그리드 간격을 제한한다.
- 데스크탑에서 쇼츠를 배경 비디오로 사용할 경우 원본 영상의 핵심 피사체가 잘리지 않도록 `object-fit: contain` 또는 중앙 프레임 + 확장 배경 방식을 우선 검토한다.
- 모바일에서는 원페이지 하단 콘텐츠를 계속 탐색할 수 있어야 하므로 가로 스와이프 중심의 인터랙션보다 세로 스크롤을 기본 탐색 방향으로 둔다.
- 모바일 쇼츠 갤러리는 한 번에 하나의 세로형 카드가 주목되도록 구성하되, 카드 아래 다음 콘텐츠 일부가 보이거나 스크롤 여백을 두어 페이지가 끝나지 않았음을 인지하게 한다.
- 모바일에서 히어로 자동재생 비디오는 음소거 상태를 유지하고, 재생 실패 또는 저전력 모드에서는 정적 썸네일 fallback을 노출한다.
- 고정 내비게이션, CTA, 언어 선택 UI가 쇼츠 하단의 다음 섹션 진입 영역을 가리지 않도록 safe-area와 하단 여백을 반영한다.

### 구간 2: 오늘의 날씨 멤버 및 OOTD 확장
- 기존 전체 멤버 카드 그리드 이전에 `오늘의 멤버` 집중 구간을 배치한다.
- 오늘 쇼츠에 등장한 멤버의 프로필, 날씨 키워드, 한 줄 메시지, 관련 트랙을 우선 노출한다.
- 영상 속 OOTD를 고화질 정지 이미지 갤러리로 제공하여 유튜브 쇼츠에서 빠르게 지나간 스타일링 정보를 웹에서 다시 탐색하도록 설계한다.
- OOTD 갤러리는 대표 컷, 디테일 컷, 세로형 모바일 컷을 구분하고, 이미지 선택 시 큰 프리뷰 또는 라이트박스가 열리는 구조를 검토한다.
- 기존 4인 멤버 소개는 하단 보조 구간으로 유지하되, 오늘 멤버 카드는 강조 상태로 연결한다.

### 구간 3: 최신 앨범 및 데일리 추천 플레이리스트
- 기존 `Discography`와 `Streaming` 구간은 통합 또는 인접 배치하여 음악 탐색 흐름을 줄인다.
- 최신 앨범 `The Prism of Nature` 정보와 트랙별 유튜브 임베드는 유지한다.
- 오늘 날씨에 맞춘 추천 플레이리스트 영역을 추가한다. 예시는 맑은 날 `Golden Hour`, 비 오는 날 `Blue Prism`, 흐린 날 `Cloud 9`, 번개/폭풍 테마 `Electric Pulse`이다.
- 플레이리스트는 Spotify 또는 YouTube Music 임베드를 우선 검토하고, 임베드가 어려운 플랫폼은 외부 링크 CTA로 대체한다.
- 트랙 리스트에는 날씨/멤버 태그를 추가해 데일리 콘텐츠와 앨범 세계관이 연결되도록 한다.

### 구간 4~5: 소셜 미디어 갤러리 및 아카이브
- 기존 유튜브 쇼츠 갤러리와 틱톡 구간은 유지하되, 최신 피드 단순 노출보다 날짜별 날씨 영상 아카이브 목적을 강화한다.
- 유튜브 쇼츠는 현재의 브라우저 프록시 스크래핑 방식 대신, 운영자가 `src/data`에 직접 관리하는 쇼츠 ID 목록을 우선 데이터 소스로 삼는 방향이 적합하다.
- 아카이브 카드에는 날짜, 날씨, 담당 멤버, 영상 플랫폼, 짧은 설명, 썸네일을 표시한다.
- 필터는 날짜, 날씨 타입, 멤버, 플랫폼 기준으로 구성한다.
- 틱톡은 현재 creator embed를 유지하되, 향후 개별 게시물 URL 목록 기반 카드 렌더링 또는 공식 API 연동 가능성을 검토한다.
- 소셜 구간의 목표는 매일 아침 유입된 사용자가 오늘 콘텐츠를 확인한 뒤, 지난 날씨 영상까지 쉽게 되짚어보게 하는 것이다.

### 구현 우선순위 제안
- 1단계: `DailyContent` 데이터 모델 정의 및 현재 정적 콘텐츠를 해당 모델에 맞춰 재배치한다.
- 2단계: 히어로를 데일리 비디오/쇼츠 중심 UI로 개편하고, 오늘의 날씨 타이포그래피와 스트리밍 CTA를 재구성한다.
- 3단계: 오늘 멤버 프로필 및 OOTD 갤러리 섹션을 신설한다.
- 4단계: 앨범/스트리밍 구간에 데일리 추천 플레이리스트를 추가한다.
- 5단계: 유튜브 쇼츠와 틱톡 구간을 날짜별 아카이브 UI로 재정리한다.
- 6단계: 자동 연동처럼 보이는 데일리 노출은 날짜 기반 하드코딩 상수 선택 로직으로 구현하고, 클라이언트 스크래핑은 제거한다.

### 별도 기재: src 싱글 렌더링 웹페이지 분석
- 현재 `src/App.tsx`는 React 단일 파일 중심의 원페이지 구조로 구성되어 있다.
- 렌더링 순서는 `Navbar`, `Hero`, `Members`, `Discography`, `Streaming`, `YouTubeShorts`, `TikTokFeed`, `Footer`이다.
- `MEMBERS`, `TRACKLIST`, `LYRICS` 등 주요 콘텐츠 데이터가 `App.tsx` 내부 상수로 직접 선언되어 있어 빠른 수정은 쉽지만, 데일리 콘텐츠 자동 교체에는 확장성이 낮다.
- 현재 히어로 구간은 `/images/hero.png` 단일 정적 이미지를 배경으로 사용하며, 스트리밍 링크만 중앙 CTA로 제공한다.
- 멤버 소개 구간은 전체 멤버 4인을 동일 가중치의 카드 그리드로 노출한다. 오늘 쇼츠 주인공 멤버를 우선 노출하거나 OOTD 컷을 확장하는 구조는 아직 없다.
- 앨범 구간은 미니 앨범 소개, 유튜브 임베드 플레이어, 트랙 리스트, 가사/크레딧 모달을 포함한다.
- 스트리밍 구간은 Spotify, YouTube Music, Apple Music 링크와 기타 플랫폼명 나열 중심이다. 날씨별 추천 플레이리스트 임베드는 아직 없다.
- 유튜브 쇼츠 구간은 브라우저에서 프록시를 통해 `@weatheridols/shorts` HTML을 가져와 `videoId`를 추출하는 방식이다. CORS, 프록시 장애, 유튜브 마크업 변경에 취약하므로 핵심 트래픽 구간의 데이터 소스로는 안정성이 낮다.
- 틱톡 구간은 TikTok creator embed 스크립트를 삽입하는 방식이며, 실제 날짜별 아카이브나 API 기반 개별 영상 갤러리 구조는 아직 없다.
- `Share2`, `Film`, `Globe`, `FEED_IMAGES`는 현재 렌더링 경로에서 사용되지 않는 항목으로 보인다. 향후 소셜 공유, 영상 아카이브, 글로벌 링크, 이미지 갤러리 기능으로 활용하거나 정리 대상이다.
